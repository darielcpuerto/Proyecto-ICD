# Metodología del proyecto

## Principio metodológico

Seguir la secuencia:

**UTILIDAD → OBJETIVO → PREGUNTAS → DATOS → RECOLECCIÓN → PROCESAMIENTO → ANÁLISIS → RESPUESTAS**

No comenzar por modelos o herramientas. Cada método debe justificarse por la pregunta y los datos disponibles.

Priorizar métodos:

- transparentes;
- interpretables;
- reproducibles;
- viables con recursos limitados.

No usar aprendizaje automático únicamente para añadir complejidad.

## Desarrollo por objetivo

Para cada objetivo avanzar mediante:

**pregunta → variable → dato → fuente → método → procesamiento → análisis → resultado.**

## Utilidad

El proyecto busca producir conocimiento respaldado por datos sobre la relación entre necesidades energéticas, posibilidades económicas y oferta observada del mercado solar.

## Datos

Para cada pregunta debe determinarse:

- qué variable se necesita;
- qué dato concreto representa esa variable;
- de qué fuente puede obtenerse;
- cómo se recogerá;
- qué unidad de observación tendrá;
- qué limitaciones presenta.

## Recolección

Los datos deben ser obtenidos por el estudiante mediante instrumentos y procedimientos documentados.

Las tres fuentes obligatorias son:

1. personas;
2. Internet;
3. instituciones.

## Preparación y procesamiento

Registrar:

- datos originales;
- limpieza;
- transformaciones;
- criterios de inclusión/exclusión;
- valores faltantes;
- normalizaciones;
- deduplicaciones;
- filtros;
- supuestos.

Conservar los datos originales cuando sea posible.

## Análisis

Las técnicas se elegirán después de conocer los datos disponibles y las preguntas. Los métodos estadísticos concretos permanecen abiertos.

## Integración

Cuando sea metodológicamente válido, relacionar:

- necesidades de las personas;
- capacidad económica;
- oferta observada;
- contexto institucional.

## Estimación energética

La lógica prevista es derivar requerimientos a partir de usos declarados.

Ejemplo conceptual:

**potencia de equipos + tiempo de uso + simultaneidad → demanda energética → almacenamiento/generación aproximados.**

Los supuestos técnicos deben documentarse y no confundirse con mediciones reales.

## Adecuación

Las soluciones observadas deben evaluarse como **potencialmente adecuadas/compatibles**, no como recomendaciones definitivas.

Los criterios de compatibilidad deben ser explícitos y reproducibles y todavía permanecen abiertos.

## Brechas

Las brechas serán resultados derivados del análisis. Podrán estudiarse brechas:

- económicas;
- técnicas;
- de demanda/oferta observada;
- de información;
- geográficas,

si los datos permiten estudiarlas.

La ausencia de información no demuestra por sí misma la ausencia del fenómeno.

## Factibilidad

El proyecto debe ser realizable aproximadamente en un mes. Se priorizan:

- recolección reproducible;
- automatización razonable;
- herramientas gratuitas;
- procesamiento ligero;
- métodos estadísticos comprensibles.

## Alcance de las inferencias

Distinguir siempre:

- población vs. muestra;
- correlación vs. causalidad;
- percepción vs. medición;
- estimación vs. dato observado;
- oferta observada vs. mercado completo;
- precio anunciado vs. precio de transacción;
- disponibilidad anunciada vs. disponibilidad verificada;
- ausencia de datos vs. ausencia del fenómeno.
